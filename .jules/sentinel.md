## 2026-07-12 - [Hardened M-Pesa Payment Validation and Edge Function JWT Authentication]
**Vulnerability:** Unauthenticated/unauthorized public access to the M-Pesa Edge Function permitted any external actor to trigger STK push requests. Additionally, a lack of server-side data validation allowed clients to submit arbitrary payment amounts and associate the transaction with arbitrary order IDs, bypassing database RLS checks during the state update due to the use of service role keys.
**Learning:** Edge Functions acting on behalf of the application with service-level privileges must explicitly verify caller identity by validating JWT signatures. Moreover, any client-submitted financial and transaction parameters (e.g., payment amounts) must be validated server-side against the database source of truth rather than blindly trusted.
**Prevention:** Always verify the incoming JWT from the Authorization header using `supabase.auth.getUser()`. Query the database record securely to check state transition rules, ownership details, and amounts before communicating with external third-party payment gateways.
