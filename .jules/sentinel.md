## 2026-07-12 - Payment Authorization and Amount Tampering in M-Pesa Edge Function
**Vulnerability:** The M-Pesa STK push Edge Function (`supabase/functions/mpesa/index.ts`) accepted caller-supplied payment amounts and initiated payment requests without verifying user authentication or validating order ownership and status against the database. Internal errors were also returned directly to clients.
**Learning:** Client-invoked payment orchestration Edge Functions that trigger third-party gateways (Daraja) must not trust the client payload for amounts or order associations; the service role client must query and enforce order status (`pending`), verify caller identity (`buyer_id === auth.uid()`), and extract amounts directly from the database record.
**Prevention:** Always authenticate Edge Function requests via Supabase Auth JWT (`supabase.auth.getUser()`), query canonical records server-side for transaction amounts, enforce order state transitions, and sanitize error responses to generic error messages while logging details internally.
