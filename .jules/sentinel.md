## 2026-07-12 - [Secure payment authorization and client mitigation in M-Pesa Edge Function]
**Vulnerability:** Client-Side Price Manipulation and Unauthenticated Payment Initialization in Deno Edge Functions.
**Learning:** Initial scaffolding for the Safaricom M-Pesa STK Push integration allowed clients to specify the payment `amount` inside the API request payload without verifying the request's authenticity or user identification. Unauthenticated callers could trigger expensive M-Pesa STK Push operations or bypass database pricing schemas by supplying low transaction values directly in the client payload. Additionally, exposing backend-specific transaction identifiers like `CheckoutRequestID` in client responses introduced risk of webhook/callback spoofing.
**Prevention:** Hardened Edge Functions must explicitly require and verify the Bearer token JWT using the Deno Supabase client, query the server-side database for the actual order price to prevent client-side parameter tampering, validate that the order status is 'pending' and belongs to the authenticated user, and sanitize all client-facing responses by omitting sensitive identifiers (such as `CheckoutRequestID`) before returning data to the frontend.
