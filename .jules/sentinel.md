## 2026-07-12 - [Critical Payment Price Manipulation and Unauthorized STK Push in M-Pesa Edge Function]
**Vulnerability:** The `mpesa` Edge Function (`supabase/functions/mpesa/index.ts`) accepted the transaction `amount` and order details directly from client-supplied HTTP request JSON bodies without verifying the user's Supabase JWT authorization or verifying the order details against the database. This allowed any unauthenticated user/client to manipulate the payment amount (e.g., set to 1 KES) or trigger arbitrary payment push alerts to unsuspecting users' mobile devices.
**Learning:** Over-reliance on client-provided parameters in payment workflows creates critical injection and pricing-bypass vulnerabilities. Edge functions run in a stateless/isolated context and must always treat client inputs as untrusted, especially for financial transactions.
**Prevention:** Always authenticate the user on the server using `supabase.auth.getUser(token)` with a trimmed/normalized token from the `Authorization` header. Retrieve payment details, item prices, and status strictly from the backend database using the `SUPABASE_SERVICE_ROLE_KEY` client to ensure integrity, ownership, and correct order status. Never rely on the client to send the price/amount.
