## 2026-06-24 - M-Pesa Price Manipulation & Authorization Bypass
**Vulnerability:** The M-Pesa Edge Function previously accepted the payment `amount` and `orderId` from the client without verifying user identity or validating the amount against the database. This allowed any user (or unauthenticated attacker) to trigger an STK Push for any order and, more critically, to specify a lower amount than the order total.
**Learning:** Supabase Edge Functions do not automatically enforce JWT verification or Row-Level Security (RLS) when invoked. They are essentially public endpoints unless manual `Authorization` header checks are implemented. Furthermore, trusting client-provided transaction values (like price/amount) is a classic business logic flaw.
**Prevention:** Always extract and verify the JWT from the `Authorization` header in Edge Functions using `supabase.auth.getUser()`. For sensitive operations like payments, fetch the source-of-truth data (e.g., `total_amount`) directly from the database using a service role client instead of relying on request body parameters.
