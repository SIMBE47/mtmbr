## 2026-07-12 - [Critical] M-Pesa Edge Function Price Manipulation & Missing Authentication
**Vulnerability:** The `mpesa` Edge Function originally allowed client-side manipulation of transaction payment amounts. An attacker could craft a POST request directly to the `/mpesa` endpoint with a custom, lowered `amount` parameter, which would then be forwarded directly to Safaricom's Daraja API for STK Push. In addition, there was no verification of the caller's JWT/identity, which meant anyone could trigger STK push requests for arbitrary phone numbers and order IDs.
**Learning:** Believing that frontend validation or local variables (like `listing.price + deliveryFee`) are sufficient is a flawed assumption. Clients can always bypass the frontend and hit public API endpoints or Edge Functions directly. Therefore, server-side parameter verification is absolutely essential.
**Prevention:** Always authenticate the user on the server/Edge Function via JWT verification using `supabase.auth.getUser()`. Always treat database records (such as orders and listings) as the single source of truth for financial operations, fetching values directly from the database using service-role access keys instead of trusting client-supplied request payloads.
