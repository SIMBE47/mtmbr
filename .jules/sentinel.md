## 2026-07-12 - [Unauthenticated Edge Functions and Client-Side Price Manipulation]
**Vulnerability:** The M-Pesa STK Push Edge Function accepted the payment `amount` directly from the client and processed the request without any authentication, authorization, or server-side order validation. This allowed any unauthenticated user to trigger arbitrary M-Pesa requests or manipulate checkout payment amounts (e.g. paying 1 KES instead of the true total amount).
**Learning:** Believing that client-side parameters are safe or that Edge Functions are automatically protected by Supabase RLS policies is a critical security gap. Edge Functions bypass user-level RLS when they are invoked or when service-role keys are used internally, so robust JWT verification and server-side database validation are mandatory.
**Prevention:** Always verify the client's `Authorization` header in Edge Functions using `supabase.auth.getUser()`, fetch the authentic order details directly from the database, and match the authenticated user's ID against the order's `buyer_id` before processing payments.
