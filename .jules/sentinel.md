## 2026-07-12 - M-Pesa STK Push Payment Amount Tampering & Missing Authorization
**Vulnerability:** The `mpesa` Edge Function accepted payment `amount` and `orderId` directly from the client request body without verifying the caller's JWT authentication or validating that the caller was the buyer who placed the order. A malicious actor could invoke the function directly with an arbitrary `amount` (e.g., KES 1 instead of the order total) or initiate payments against orders belonging to other users.
**Learning:** Edge Functions in Supabase operate outside PostgreSQL Row Level Security (RLS) unless explicit JWT extraction and validation (`supabase.auth.getUser()`) is performed. Financial transactions must treat client-provided prices/amounts as untrusted and fetch the canonical total directly from the database using service-role queries verified against the authenticated user.
**Prevention:** Always authenticate the caller in Edge Functions handling billing, verify that the order's `buyer_id` matches the authenticated `user.id`, confirm the order is in `pending` status, and read the transaction amount directly from the trusted database order record.
